不用抽象定义，直接用一个**具体例子**把整个过程走一遍。看完应该就能明白 Circom、snarkjs、Groth16 各自在干什么。

---

## 一、先设定一个目标

假设我是证明者 Peggy，我想向你（验证者 Victor）证明：

> **我知道一个秘密数字 `a`，满足 `a × 3 = 15`，但我不想告诉你 `a` 是多少。**

你知道的是：
- 公开数字：`b = 3`
- 公开结果：`c = 15`

我知道的是：
- 秘密数字：`a = 5`

零知识证明要做的就是：**我让你相信“我确实知道 a=5”，但整个过程不泄露 a=5。**

---

## 二、三个东西分别是什么角色？

| 名字 | 通俗理解 | 实际作用 |
|---|---|---|
| **Circom** | 写“题目规则”的语言 | 把 `a × 3 = 15` 变成数学电路，编译成 R1CS 和 WASM |
| **Groth16** | 一套“证明数学方法” | 规定如何根据电路和秘密生成小证明，以及如何验证 |
| **snarkjs** | 干活的工具箱 | 调用 Groth16，实际执行设置、生成证明、验证证明 |

一句话：
> **Circom 出题，Groth16 是解题和判卷的数学原理，snarkjs 是帮你实际做题和判卷的工具。**

---

## 三、完整流程，一步一步来

### 第 0 步：写电路（Circom）

我们用 Circom 写一个电路文件 `multiplier.circom`：

```circom
pragma circom 2.0.0;

template Multiplier() {
    signal input a;   // 秘密输入
    signal input b;   // 公开输入
    signal output c;  // 公开输出

    c <== a * b;
}

component main {public [b]} = Multiplier();
```

解释：
- `a` 是私有输入，只有我知道。
- `b` 是公开输入，大家知道是 3。
- `c` 是输出，大家知道是 15。
- `c <== a * b` 就是约束：输出必须等于 a 乘 b。

这个电路表达的就是：**存在一个 a，使得 a × b = c。**

---

### 第 1 步：编译电路（Circom 干活）

运行：

```bash
circom multiplier.circom --r1cs --wasm --sym
```

会得到几个文件：

| 文件 | 作用 |
|---|---|
| `multiplier.r1cs` | 电路的数学约束系统，告诉证明系统“规则是什么” |
| `multiplier.wasm` | 一个程序，用来根据输入计算所有中间值（witness） |
| `multiplier.sym` | 调试用，记录信号名字 |

**R1CS 是什么？**
它是 Rank-1 Constraint System，简单说就是把电路拆成一条条约束，比如：
- `c = a * b`
- 可能还有中间变量约束。

Groth16 只认识这种约束系统，所以 Circom 要把人类写的电路翻译成 R1CS。

---

### 第 2 步：可信设置（snarkjs + Groth16）

Groth16 有一个特点：**每个电路都需要一次“可信设置”**，生成证明密钥和验证密钥。

你可以理解为：Groth16 需要提前准备一套“锁和钥匙”：
- 证明者拿“证明密钥”来生成证明。
- 验证者拿“验证密钥”来验证证明。

命令大概这样：

```bash
# 先生成一个通用的 powers of tau 文件（这里省略细节）
snarkjs powersoftau new bn128 12 pot12_0000.ptau
snarkjs powersoftau contribute pot12_0000.ptau pot12_0001.ptau --name="First"
snarkjs powersoftau prepare phase2 pot12_0001.ptau pot12_final.ptau

# 针对我们的电路做 Groth16 setup
snarkjs groth16 setup multiplier.r1cs pot12_final.ptau multiplier_0000.zkey

# 多方贡献，降低信任风险
snarkjs zkey contribute multiplier_0000.zkey multiplier_final.zkey --name="My contribution"

# 导出验证密钥
snarkjs zkey export verificationkey multiplier_final.zkey verification_key.json
```

得到关键文件：
- `multiplier_final.zkey`：证明密钥，证明者用来生成证明。
- `verification_key.json`：验证密钥，验证者用来验证证明。

**为什么需要可信设置？**
因为 Groth16 的数学构造里有一些秘密参数，如果被人知道，就能伪造证明。所以大家用“多方计算仪式”来生成这些参数，只要有一个参与者诚实销毁秘密，整个设置就是安全的。

# 完整过程:

### Groth16 可信设置完整流程（snarkjs）

### 前置：编译电路

```bash
circom multiplier.circom --r1cs --wasm --sym
```

生成 `multiplier.r1cs`，可信设置只依赖这个文件。

---

### 第一阶段：Powers of Tau（通用设置）

```bash
# 1. 启动新的 Powers of Tau 仪式
# 12 表示支持 2^12 = 4096 个约束，电路更大就用 13、14、15...
snarkjs powersoftau new bn128 12 pot12_0000.ptau -v

# 2. 第一次贡献随机性
snarkjs powersoftau contribute pot12_0000.ptau pot12_0001.ptau --name="First contribution" -v -e="some random text 1"

# 3. 第二次贡献随机性（可重复多次，每次输入上一次输出）
snarkjs powersoftau contribute pot12_0001.ptau pot12_0002.ptau --name="Second contribution" -v -e="some random text 2"

# 4. 准备 Phase 2
snarkjs powersoftau prepare phase2 pot12_0002.ptau pot12_final.ptau -v

# 5. 验证最终文件
snarkjs powersoftau verify pot12_final.ptau
```

如果输出 `Powers Of tau file OK!`，第一阶段完成。

---

### 第二阶段：Groth16 电路特定设置

```bash
# 6. 针对具体电路生成初始证明密钥
snarkjs groth16 setup multiplier.r1cs pot12_final.ptau multiplier_0000.zkey

# 7. 为电路特定设置贡献随机性
snarkjs zkey contribute multiplier_0000.zkey multiplier_final.zkey --name="My contribution" -v -e="some random text 3"

# 8. 可重复多次贡献（可选）
snarkjs zkey contribute multiplier_final.zkey multiplier_final_2.zkey --name="Second contribution" -v -e="some random text 4"

# 9. 导出验证密钥
snarkjs zkey export verificationkey multiplier_final_2.zkey verification_key.json
```

如果只做一次贡献，第 8 步可省略，第 9 步直接导出 `multiplier_final.zkey`：

```bash
snarkjs zkey export verificationkey multiplier_final.zkey verification_key.json
```

---

### 最终产物

| 文件 | 用途 | 给谁 |
|---|---|---|
| `multiplier_final.zkey`（或多次贡献后的最终 `.zkey`） | 证明密钥，用来生成证明 | 证明者 |
| `verification_key.json` | 验证密钥，用来验证证明 | 验证者（公开） |

---

### 为什么需要可信设置？

Groth16 在生成参数时会引入一些秘密随机数，俗称“有毒废料”。  
如果这些随机数泄露，任何人都能伪造证明。  
所以用“多方计算仪式”来生成参数：每个参与者贡献自己的随机性。  
只要**至少有一个参与者诚实销毁了自己的秘密**，最终参数就是安全的。

---

### 注意事项

- `12` 表示支持 4096 个约束。如果电路更大，用 `13`（8192）、`14`（16384）等。
- 测试环境可以单方快速跑通；生产环境必须多方参与。
- `-e` 用于非交互式指定随机文本，也可以省略，手动输入。
- 每次 `contribute` 的输入是上一次的输出，最后一个人输出最终文件。


---

### 第 3 步：准备输入（证明者本地做）

我作为证明者，准备好我的秘密和公开输入：

`input.json`：

```json
{
  "a": 5,
  "b": 3
}
```

注意：`a=5` 是秘密，`b=3` 是公开的。

---

### 第 4 步：计算 witness（snarkjs 干活）

witness 的意思是“见证”，也就是电路中所有信号的具体值。

运行：

```bash
snarkjs wtns calculate multiplier.wasm input.json witness.wtns
```

`multiplier.wasm` 是 Circom 编译出来的程序，它会根据输入：
- 读取 `a=5, b=3`
- 计算 `c = a * b = 15`
- 把所有信号值写进 `witness.wtns`

所以 `witness.wtns` 里面包含：
- `a = 5`
- `b = 3`
- `c = 15`

这个文件**只在证明者本地使用，不会发给验证者**。

---

### 第 5 步：生成证明（snarkjs + Groth16）

现在我有：
- 证明密钥：`multiplier_final.zkey`
- 见证：`witness.wtns`

运行：

```bash
snarkjs groth16 prove multiplier_final.zkey witness.wtns proof.json public.json
```

生成两个文件：

| 文件 | 内容 | 给谁 |
|---|---|---|
| `proof.json` | 零知识证明，几个椭圆曲线点 | 发给验证者 |
| `public.json` | 公开输入和输出，比如 `b=3, c=15` | 发给验证者 |

`proof.json` 里面**不包含 `a=5`**。它只是一个数学证明，证明“我知道一个 a，使得 a×3=15”。

这就是零知识：验证者拿到证明后，能确认我知道秘密，但无法反推出秘密。

---

### 第 6 步：验证证明（snarkjs + Groth16）

验证者 Victor 拿到：
- `verification_key.json`
- `public.json`
- `proof.json`

运行：

```bash
snarkjs groth16 verify verification_key.json public.json proof.json
```

snarkjs 会调用 Groth16 的验证算法，检查：
- 证明是否由正确的证明密钥生成？
- 公开输入 `b=3, c=15` 是否与证明一致？
- 是否存在某个秘密 `a` 满足电路？

如果输出 `OK`，验证通过。

验证者全程不知道 `a=5`。

---

### 第 7 步：链上验证（可选）

如果要在以太坊上验证，可以导出 Solidity 验证合约：

```bash
snarkjs zkey export solidityverifier multiplier_final_2.zkey verifier.sol
```

部署 `verifier.sol` 后，任何人都可以调用 `verifyProof`，传入 `proof.json` 和 `public.json` 里的数据，链上合约会返回 true/false。

## 四、整个流程图

```text
你写电路 (.circom)
      |
      v
Circom 编译
      |
      +--> R1CS（约束系统）------> snarkjs + Groth16 setup ---> zkey（证明密钥）
      |                                                       |
      |                                                       +--> verification_key.json（验证密钥）
      |
      +--> WASM（witness 计算器）
                |
                v
输入 input.json（a=5, b=3）
                |
                v
snarkjs wtns calculate ---> witness.wtns（a=5, b=3, c=15）
                |
                v
snarkjs groth16 prove + zkey + witness
                |
                +--> proof.json（证明）
                +--> public.json（公开输入输出）
                |
                v
验证者：snarkjs groth16 verify + verification_key.json + public.json + proof.json
                |
                v
              OK / 失败
```

---

## 五、三者关系再总结

- **Circom**：把“我想证明的计算”写成电路，编译成 R1CS 和 WASM。
- **Groth16**：一种 zk-SNARK 协议，定义了如何根据 R1CS 和 witness 生成证明、验证证明。它需要可信设置。
- **snarkjs**：一个工具包，实际执行 Groth16 的 setup、prove、verify，并导出 Solidity 验证器。

所以：
> **Circom 是前端语言，snarkjs 是工具链，Groth16 是后端证明协议。**
> 你用 Circom 写电路，用 snarkjs 调用 Groth16，最终生成一个很小的证明，让验证者相信你知道秘密，而不泄露秘密。

这样整个过程就串起来了。
